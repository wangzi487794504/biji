## 排版规范（核心）

以下规则从第一章（神经网络.md）的最终定稿中提取，所有后续章节必须严格遵守。

### 标题层级

```
### 一、从函数到神经网络            ← 章标题（H3）
#### 1.1 线性函数：为什么...        ← 节标题（H4）
##### 用山丘拼出任意函数             ← 子节标题（H5，仅在内容足够复杂时使用）
```

- 章标题用中文数字（一、二、三…），格式：`### 章号、章名`
- 节标题用阿拉伯数字（1.1, 1.2…），格式：`#### 节号 节名：副标题`
- 副标题常为"为什么…"或"从…到…"的问题/因果句式

### 正文段落

```
* 这是正文段落。用星号+空格开头，正文中关键术语用**粗体**标注，首次出现的概念必须加粗。
  段落内长句自然换行。句子之间用中文标点衔接——破折号、逗号、句号。
```

- **所有正文段落**以 `* ` 开头（星号 + 空格）
- 首次出现的关键术语用 `**粗体**` 标记
- 段落之间用空行分隔

### 小标题（不加星号的行内加粗标签）

```
**第一层**（n 个线性函数并行，每个有自己的一套权重）：
**第二层**（把第一层的 n 个输出做加权组合）：
**定理保证的**：
**定理没保证的**：
**均方误差（MSE）—— 回归任务的标配**
```

- 用 `**text**：` 或 `**text**——副标题` 格式
- 不加 `* ` 前缀，不缩进
- 用于段落内的小标题或标签

### 过渡句

```
好，回到正题。把第一层的 h₁, h₂, ..., hₙ 全部代入...
但先回到眼前的问题。全连接层尽管有这些缺陷...
```

- 叙事中需要"拉回主线"或"暂时搁置"时的过渡句，**不加 `* ` 前缀**
- 通常是短句（< 50 字），起到承上启下的作用

### 子要点/列表

```
* 现在你手上有一批这样的山丘。每个山丘由两个（或一组）ReLU 生成，有四个可调参数：
  - **位置**（拐点在哪里）——由权重和偏置控制
  - **宽度**（山丘有多宽）——由两个拐点之间的距离控制
  - **高度**（山丘有多高）——由输出权重控制
  - **形状**（尖的还是平的）——由 ReLU 的组合方式控制
```

- 主句以 `* ` 开头，用冒号收尾
- 子项以 `  - ` 开头（两个空格 + 短横 + 空格）
- 子项中用 `——` 连接术语和解释

### 有序列表

```
1. 接收来自上一层的输入 x₁, x₂, ...
2. 做线性组合 z = w₁x₁ + w₂x₂ + ... + b
3. 通过激活函数：a = ReLU(z)
```

- 用于步骤、流程、序列

### 关键结论 / 转折框

```
> 单层线性函数，表达能力太弱。
> 堆叠解决不了问题。线性 + 线性 = 线性。我们需要的是**非线性**。
> 最终的 y 依然可以写成 x₁, x₂, ..., x₃₀₀₀₀₀₀ 的一个线性组合。
```

- 用 `> ` 引用块
- 用于：核心结论、因果链的转折点、一句总结
- 通常放在一段正文叙述之后，作为"点睛"

```

## 叙事风格（核心）

### 因果链结构

每一节必须遵循：**问题 → 尝试方案 → 暴露新问题 → 新方案**

```
例：
1. 线性函数一刀切分不开 → 多叠几层？
2. 代数证明：线性+线性=线性，堆叠无效 → 需要非线性
3. 引入激活函数 ReLU → 解决了非线性，但神经元散乱无序
4. 全连接层系统组织 → 解决了组织，但参数爆炸+空间盲
...
```

不是罗列知识点，而是讲一个"困境→突破→新困境"的故事。

### 具体先于抽象

- 每引入一个新概念，先用具体数字/例子演示，再给出通用公式
- 例子要可追踪（具体的输入值、具体的权重、算出具体的输出）

### 自我纠错

允许展示"试错"过程：
```
这个例子选得不太好——两个 ReLU 相减产生的是一个台阶…更清晰的构造是…
```

### 类比服务于直觉

- 数学推导之后，用生活类比帮读者建立直觉
- 类比要准确，不能为了通俗而牺牲正确性

### 禁止事项

- ❌ 不要在正文中使用 emoji（🧠🤖📊 等）
- ❌ 不要写"大家可以想象…""相信大家已经…"等空洞过渡
- ❌ 不要堆砌标题（能合并的小节就合并）
- ❌ 不要跳过数学推导（每个公式都要解释"为什么长这样"）
- ❌ 不要用英文术语替代中文（第一次出现时中文+英文括号标注）

## 四个Agent角色

### 1. 执行Agent (Execution Agent)
- 撰写新内容，修订现有内容
- 必须严格遵守本 skill 的排版规范

### 2. 打分Agent (Scoring Agent)
- 维度：技术准确性、完整性、可读性、教育价值、一致性
- 综合评分 < 7.5 触发修订

### 3. 监督Agent (Supervision Agent)
- 检查：小节划分、逻辑流、大纲覆盖、章节衔接
- 特别关注因果链是否完整

### 4. 守护Agent (Guardian Agent)
- 检查：数学公式、技术概念、术语一致性、易误解表述
- 发现技术错误必须修正
