#### Spring AI之结构化输出和多模态

* LLM 生成结构化输出的能力对于依赖于可靠解析输出值的下游应用程序至关重要。开发人员希望能够快速地将 AI 模型的结果转换为 JSON、XML 或 Java 类等数据类型，以便传递给其他应用程序函数和方法。

  <img src="C:\Users\踽踽独行\AppData\Roaming\Typora\typora-user-images\image-20260309212955409.png" alt="image-20260309212955409" style="zoom:80%;" />

* 在调用 LLM 之前，转换器会在提示符后附加格式指令，为模型生成所需的输出结构提供明确的指导。这些指令如同蓝图，引导模型的响应符合指定的格式。

  * 其核心原理是在LLM的调用前后进行干预，分为两种模式：
    - **传统模式：基于提示词格式化**
      1. **调用前（增强提示）**：转换器会**自动将格式指令追加到提示词末尾**。明确告诉模型应该以何种结构（如JSON Schema）返回数据。
      2. **调用后（解析输出）**：模型返回文本后，转换器的`Converter`部分负责**解析原始文本**，并将其映射、转换为你在代码中指定的目标类型（如Java Class、Map、List）。
    - **现代模式：原生结构化输出**：对于支持此功能的模型（如GPT-4o），Spring AI可以通过`AdvisorParams.ENABLE_NATIVE_STRUCTURED_OUTPUT`启用更可靠的方式。此时，**不再需要在提示词中添加格式指令**，而是直接将JSON Schema通过模型的原生API发送。模型**内部保证**返回符合该Schema的结构化数据，这种方式更可靠，提示词也更简洁。

* 转换器的核心是 `StructuredOutputConverter<T>` 接口。它巧妙地组合了两个子接口

  ```java
  public interface StructuredOutputConverter<T> extends Converter<String, T>, FormatProvider {
  }
  ```

  * **`FormatProvider`**：负责提供格式化指令（即`getFormat()`方法）。这些指令会被注入到提示词中，引导模型生成符合预期的文本。
  * **`Converter<String, T>`**：这是Spring框架的核心转换接口。负责将模型返回的`String`类型输出，转换为目标类型 `T`。

* Spring AI提供了几种开箱即用的转换器，覆盖了常见需求。

  | 转换器                                     | 核心功能                                                     | 适用场景                                                     | 代码示例片段 (ChatClient API)                                |
  | :----------------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
  | **`BeanOutputConverter<T>`**               | **最常用**。将JSON输出转换为**POJO或Record**。它根据你的Java类生成JSON Schema作为格式指令。 | 当你需要从模型提取具有明确字段结构的信息时，例如解析人物的电影作品列表、提取商品信息、分析用户意图等。 | `ActorsFilms result = ChatClient.create(chatModel).prompt() .user("Generate filmography for Tom Hanks.") .call() .entity(ActorsFilms.class);` |
  | **`MapOutputConverter`**                   | 将JSON输出转换为 **`Map<String, Object>`**。                 | 当返回的数据结构是动态的、不确定的，或者你不想为它专门创建一个Java类时非常方便。例如解析一个属性可变的配置信息。 | `Map<String, Object> result = ChatClient.create(chatModel).prompt() .user("Give me a map of ...") .call() .entity(new ParameterizedTypeReference<Map<String, Object>>() {});` |
  | **`ListOutputConverter`**                  | 将**逗号分隔**的文本列表转换为 **`List<String>`**。          | 适用于简单的、基于文本的列表生成任务，例如生成五个冰淇淋口味、列出三个学习要点等。 | `List<String> flavors = ChatClient.create(chatModel).prompt() .user("List five ice cream flavors") .call() .entity(new ListOutputConverter(new DefaultConversionService()));` |
  | `AbstractConversionServiceOutputConverter` | 抽象类，利用Spring的`ConversionService`进行灵活转换。        | 需要自定义复杂的转换逻辑，但不想自己处理`FormatProvider`时，可以扩展此类。 | -                                                            |
  | `AbstractMessageOutputConverter`           | 抽象类，利用Spring的`MessageConverter`进行转换。             | 适用于需要将输出转换为消息（如电子邮件、HTTP响应体）的场景。 | -                                                            |

* 处理泛型与复杂类型：使用 `ParameterizedTypeReference` 可以优雅地处理如 `List<ActorsFilms>` 这样的泛型类型，这在低层API和高层`ChatClient` API中都得到支持。

  ```java
  List<ActorsFilms> filmographies = ChatClient.create(chatModel).prompt()
      .user("Generate filmography for Tom Hanks and Bill Murray.")
      .call()
      .entity(new ParameterizedTypeReference<List<ActorsFilms>>() {});
  ```

* 控制JSON属性顺序**：如果你的应用对生成的JSON有严格的顺序要求（如用于签名验证），可以使用`@JsonPropertyOrder`注解来精确控制`BeanOutputConverter`生成的JSON Schema及最终输出的属性顺序。

  ```java
  @JsonPropertyOrder({"actor", "movies"})
  record ActorsFilms(String actor, List<String> movies) {}
  ```

* 利用模型内置的JSON模式：文档中还提到了，对于一些模型（如OpenAI、Ollama），可以直接在模型选项（`ChatOptions`）中配置`responseFormat`为`json`。这可以作为`StructuredOutputConverter`的一个补充或底层实现基础，进一步确保模型以JSON格式响应。

* **始终牢记**：转换过程不是100%可靠的，对关键业务数据增加一层**后处理验证**是良好的工程实践。

  

  

  

  

#### 多模态

* 新一代多模态大型语言模型开始涌现。例如，OpenAI 的 GPT-4o、谷歌的 Vertex AI Gemini 1.5、Anthropic 的 Claude3 以及开源模型 Llama3.2、LLaVA 和 BakLLaVA 等，它们能够接收包括文本、图像、音频和视频在内的多种输入，并通过整合这些输入生成文本回复。

  <img src="C:\Users\踽踽独行\AppData\Roaming\Typora\typora-user-images\image-20260309222728401.png" alt="image-20260309222728401" style="zoom:80%;" />

* UserMessage`content`字段主要用于文本输入，而可选`media`字段允许添加一个或多个不同模态的附加内容，例如图像、音频和视频。该字段`MimeType`指定模态类型。根据所使用的 LLM，`Media`数据字段可以是原始媒体内容对象，`Resource`也可以`URI`是内容的引用。
