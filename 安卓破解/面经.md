####  面经

* 安卓四大组件

  * Activity（活动）、Service（服务）、Broadcast Receiver（广播接收器）和 Content Provider（内容提供者）

    * Activity（活动）
      - **功能**：是安卓应用中最基本的组件，用于实现用户界面。一个 Activity 通常对应一个屏幕的内容，它提供了一个可视化的界面，让用户可以与应用进行交互，如点击按钮、输入文本、查看图片等。
      - **启动方式**：通过 Intent 来启动，可以是显式 Intent（明确指定要启动的 Activity），也可以是隐式 Intent（根据动作、类别等信息来查找匹配的 Activity）。
      - **生命周期**：包括 onCreate ()、onStart ()、onResume ()、onPause ()、onStop ()、onDestroy () 等方法，开发者可以根据需求在不同的生命周期方法中进行相应的操作，如在 onCreate () 中进行初始化工作，在 onPause () 中保存数据等。
    * Service（服务）
      - **功能**：用于在后台执行长时间运行的操作，不提供用户界面。例如，音乐播放服务、文件下载服务、数据同步服务等。服务可以在应用程序的后台运行，即使应用程序的界面不可见，也能继续执行任务。
      - **启动方式**：有两种启动方式，一是通过 startService () 方法启动，这种方式启动的服务会一直运行，直到被停止；二是通过 bindService () 方法启动，这种方式可以让组件与服务进行绑定，通过接口与服务进行通信。
      - **生命周期**：有 onCreate ()、onStartCommand ()、onBind ()、onUnbind ()、onDestroy () 等方法。startService () 方式启动时，会调用 onCreate () 和 onStartCommand () 方法；bindService () 方式启动时，会调用 onCreate () 和 onBind () 方法。
    * Broadcast Receiver（广播接收器）
      - **功能**：用于接收系统或应用程序发出的广播消息。广播可以是系统广播，如电池电量变化、网络连接变化等，也可以是应用程序自定义的广播。广播接收器可以在接收到广播后执行相应的操作，如更新界面、启动服务等。
      - **注册方式**：有静态注册和动态注册两种方式。静态注册是在 AndroidManifest.xml 文件中进行注册，这种方式注册的广播接收器在应用程序安装后就一直处于监听状态；动态注册是在代码中通过 registerReceiver () 方法进行注册，这种方式注册的广播接收器在注册后才开始监听广播，当不需要时可以通过 unregisterReceiver () 方法取消注册。
      - **生命周期**：广播接收器的生命周期非常短暂，当接收到广播后，会在 onReceive () 方法中处理广播消息，一旦 onReceive () 方法执行完毕，广播接收器的生命周期就结束了。
    * Content Provider（内容提供者）
      - **功能**：用于在不同的应用程序之间共享数据。例如，联系人数据、短信数据等可以通过 Content Provider 提供给其他应用程序访问。Content Provider 提供了一组标准的接口，用于查询、插入、更新和删除数据。
      - **使用方式**：其他应用程序可以通过 ContentResolver 来访问 Content Provider 提供的数据。通过 ContentResolver 的 query ()、insert ()、update () 和 delete () 方法来操作 Content Provider 中的数据。
      - **实现方式**：开发者需要继承 ContentProvider 类，并重写 query ()、insert ()、update ()、delete () 等方法，来实现对数据的操作。同时，需要在 AndroidManifest.xml 文件中注册 Content Provider。

  * activity的生命周期

    * 主要的生命周期方法

    1. **onCreate**：当 Activity 第一次被创建时调用，在这个方法中通常会进行一些初始化操作，如设置布局、初始化视图组件、绑定数据等。
    2. **onStart**：在 Activity 即将可见时调用，此时 Activity 已经被创建，但还没有出现在前台，用户还无法与它进行交互。
    3. **onResume**：当 Activity 进入前台并开始与用户交互时调用，此时 Activity 处于运行状态，用户可以操作界面元素。
    4. **onPause**：当 Activity 失去焦点但仍然可见时调用，例如用户点击了一个对话框或者启动了一个新的 Activity，导致当前 Activity 部分被遮挡。在这个方法中，通常需要保存一些重要的数据，以防止数据丢失。
    5. **onStop**：当 Activity 完全不可见时调用，此时 Activity 被其他 Activity 覆盖或者应用程序被切换到后台。可以在这个方法中进行一些资源释放的操作。
    6. **onDestroy**：当 Activity 被销毁时调用，这是 Activity 生命周期的最后一个方法，在这个方法中，需要释放所有与该 Activity 相关的资源，如解除注册的广播接收器、关闭数据库连接等。
    7. **onRestart**：当 Activity 从停止状态重新启动时调用，即 Activity 之前被停止，现在又要重新回到前台可见状态。

    * 生命周期状态变化示例

    - **正常启动流程**：`onCreate` -> `onStart` -> `onResume`。例如，用户点击应用图标启动应用，此时 Activity 会依次调用这三个方法，完成初始化并进入运行状态。
    - **退居后台流程**：`onPause` -> `onStop`。当用户按下手机的 Home 键或者启动了其他 Activity，当前 Activity 会先调用`onPause`方法，然后如果完全被遮挡，会再调用`onStop`方法，进入停止状态。
    - **回到前台流程**：`onRestart` -> `onStart` -> `onResume`。当用户再次切换到该 Activity 时，它会先调用`onRestart`方法，然后依次调用`onStart`和`onResume`方法，重新回到运行状态。
    - **关闭 Activity 流程**：`onPause` -> `onStop` -> `onDestroy`。当用户关闭 Activity，例如点击返回键或者通过代码调用`finish`方法，Activity 会依次执行这三个方法，完成资源释放和销毁操作。
  
* activity的启动模式

  * standard（标准模式）

    - **特点**：这是 Activity 默认的启动模式。每次启动一个 Activity，系统都会创建一个新的实例，并将其压入调用者的任务栈栈顶，不管这个实例是否已经存在。

    - **应用场景**：适用于大多数普通的 Activity，比如新闻详情页，每次打开新闻详情都需要一个新的页面实例。

  * singleTop（栈顶复用模式）

    - **特点**：如果要启动的 Activity 已经位于任务栈的栈顶，系统将不会创建新的 Activity 实例，而是复用栈顶的实例，并调用其`onNewIntent()`方法。若不在栈顶，则会创建新的实例。

    - **应用场景**：适用于接收通知启动的内容显示页，比如浏览器的通知提示，当用户点击通知时，如果浏览器的主界面已经在栈顶，就可以复用该界面并更新内容。

  * singleTask（栈内复用模式）

    - **特点**：若要启动的 Activity 在任务栈中已经存在，系统不会创建新的实例，而是将该 Activity 之上的所有 Activity 出栈，使其位于栈顶，并调用其`onNewIntent()`方法。若不存在，则创建新的实例并压入栈中。

    - **应用场景**：适用于应用的主界面，比如微信的主界面，无论从哪个界面返回主界面，都可以直接复用已存在的主界面实例。

  * singleInstance（单实例模式）

    - **特点**：系统会为该 Activity 创建一个新的任务栈，并将其放入该栈中，且该栈中只有这一个 Activity 实例。当再次启动该 Activity 时，会直接复用这个实例。

    - **应用场景**：适用于需要全局唯一的 Activity，比如闹钟提醒界面、来电界面等，确保无论从哪个应用启动该界面，都只会有一个实例存在。、

* 安卓线程间通信方式

  * Handler 机制是安卓中最常用的线程间通信方式，主要由 Handler、Message、MessageQueue 和 Looper 四个部分组成。Handler 用于发送和处理消息，Message 是携带数据的消息对象，MessageQueue 是消息队列，用于存储消息，Looper 是消息循环器，用于从消息队列中取出消息并分发给相应的 Handler 处理。
  * AsyncTask 是安卓提供的一个轻量级异步任务类，它封装了线程池和 Handler，方便开发者在子线程中执行耗时操作，并在主线程中更新 UI
  * `runOnUiThread`是 Activity 提供的一个方法，它可以在子线程中直接切换到主线程执行代码

* 安卓进程间通信方式

  * `Bundle` 本质上是一个键值对容器，可在 `Intent` 里传递数据，达成进程间通信。它支持多种基本数据类型、实现了 `Serializable` 或 `Parcelable` 接口的对象。
  * 文件共享：不同进程通过读写同一文件来交换数据。这种方式实现简单，但对并发访问的处理比较复杂，且读写文件的效率较低。
  * ContentProvider：是安卓提供的一种标准的进程间数据共享方式，以表的形式组织数据，并提供了一套标准的方法来进行数据的增删改查操作。

* view的绘制流程

  * 在 Android 中，View 的绘制流程主要分为测量（Measure）、布局（Layout）、绘制（Draw）三个阶段
  * 测量阶段
    * 此阶段用于确定 View 的大小，即测量 View 的宽和高。
    * 当 View 树的根 View 调用 `measure()` 方法时，测量过程开始，该方法会遍历整个 View 树，递归地调用每个子 View 的 `measure()` 方法。
    * 在测量过程中，每个 View 都会根据自身的布局参数以及父容器的约束来计算自己的测量尺寸。
    * 测量完成后，View 的测量宽度和高度可以通过 `getMeasuredWidth()` 和 `getMeasuredHeight()` 方法获取。
  * 布局阶段
    * 确定 View 在父容器中的位置。
    * 根 View 调用 `layout()` 方法，这个方法同样会在 View 树中递归调用，为每个子 View 分配位置。
    * 在 `layout()` 方法中，会根据测量阶段得到的 View 大小以及父容器的布局规则，计算出每个子 View 的左上角坐标（left、top）和右下角坐标（right、bottom），从而确定其在父容器中的具体位置。
  * 绘制阶段
    * 负责将 View 绘制到屏幕上。
    * 当 View 树的根 View 调用 `draw()` 方法时，绘制过程开始。
    * 绘制过程包括以下几个步骤：首先绘制背景（如果有）；然后绘制 View 的内容，如文本、图像等；接着绘制子 View（如果有）；最后绘制装饰，如滚动条等。

* 触摸事件的传递

  * 触摸事件通过 MotionEvent 类描述，主要类型有：
    - **ACTION_DOWN**：用户手指按下屏幕操作，标志一次触摸事件开始 ，一次触摸操作必定产生该事件。
    - **ACTION_MOVE**：用户手指按下后，在松开前，若滑动距离超一定阈值会触发。一般轻微移动也可能触发 ，不是每次触摸操作都有。
    - **ACTION_UP**：用户手指离开屏幕操作，标志一次完整触摸事件结束 ，一次触摸操作必定产生该事件。
  * 三个阶段
    * **分发（Dispatch）**：通过`dispatchTouchEvent(MotionEvent ev)`方法进行 。该方法返回值为 true ，表示当前视图消费事件，不再分发；返回`super.dispatchTouchEvent(ev)` ，表示继续分发。若当前视图是 ViewGroup 及其子类，会调用`onInterceptTouchEvent(ev)`判断是否拦截事件。
    * **拦截（Intercept）**：仅 ViewGroup 及其子类有`onInterceptTouchEvent(MotionEvent ev)`方法 。返回 true 表示拦截事件，不再分发给子视图，且交由自身`onTouchEvent(ev)`方法消费；返回 false 或`super.onInterceptTouchEvent(ev)` ，表示不拦截，继续传给子视图。
    * **消费（Consume）**：由`onTouchEvent(MotionEvent event)`方法处理 。返回 true 表示当前视图能处理事件，不再向上传递给父视图；返回 false 表示当前视图不处理，事件会传递给父视图的`onTouchEvent`方法处理。

* activityA启动后打开activityB，两个activity的状态经历了哪些周期？

  * A的生命周期
    * **`onPause()`**：当`ActivityA`启动`ActivityB`时，`ActivityA`会先调用`onPause()`方法。此时`ActivityA`失去焦点，但仍然可见，可进行一些轻量级的暂停操作，如暂停动画、释放一些非关键资源等。
    * **`onStop()`**：如果`ActivityB`完全覆盖了`ActivityA`，`ActivityA`会接着调用`onStop()`方法。此时`ActivityA`不再可见，可进行一些更重量级的停止操作，如停止数据库连接、注销广播接收器等。但如果`ActivityB`是透明的或者是一个对话框样式的`Activity`，`ActivityA`不会调用`onStop()`方法。
  * B的生命周期
    * **`onCreate()`**：`ActivityB`被创建时，首先会调用`onCreate()`方法。在这个方法中，通常会进行一些初始化操作，如设置布局、初始化视图组件、绑定数据等。
    * **`onStart()`**：`onCreate()`方法执行完毕后，会调用`onStart()`方法。此时`ActivityB`已经可见，但还没有获得焦点。
    * **`onResume()`**：`ActivityB`获得焦点并开始与用户交互时，会调用`onResume()`方法。此时`ActivityB`处于活动状态，用户可以在这个`Activity`上进行操作。

* 可以在子线程里面刷新UI吗？如果我非要在子线程里刷新了UI呢？会怎么样？会抛出什么异常？

  * Android 的 UI 操作不是线程安全的，如果在子线程中刷新 UI，可能会导致以下问题：
    * **界面显示异常**：由于多个线程同时访问和修改 UI 组件，可能会导致界面出现混乱、闪烁、数据显示不一致等问题，影响用户体验。
    * **程序崩溃**：可能会引发各种未定义的行为，最终导致应用程序崩溃，并抛出 `android.view.ViewRootImpl$CalledFromWrongThreadException` 异常，提示不能在子线程中访问 UI 线程的对象。

* 一个点击事件点击结束后是怎么被销毁的？

  * 事件传递与处理
    * 当用户点击屏幕时，系统会将点击事件包装成`MotionEvent`对象，并按照视图树的层级结构进行传递。从最外层的视图容器开始，依次向下传递，直到找到能够处理该点击事件的视图。
    * 视图在接收到点击事件后，会根据自身的状态和属性来决定是否消费该事件。如果一个视图消费了点击事件，那么它会调用相应的点击事件处理方法，如`onClick()`方法。
  * 事件点击完成后
    * 当点击事件处理方法执行完毕后，点击事件的处理流程就结束了。此时，系统会将`MotionEvent`对象进行回收，以便下次使用。
    * 对于视图本身，如果它在点击事件处理过程中没有发生状态改变或其他持久化的操作，那么它会恢复到点击前的状态。例如，按钮在被点击后会恢复到正常的显示状态，不会一直保持按下的外观。

* application的oncreate和activity的oncreate有什么区别?

  * **`Application.onCreate()`**：主要用于应用程序级别的全局初始化操作，比如初始化第三方库（如图片加载库、日志记录库等）、配置全局变量、初始化数据库连接、注册全局的事件监听器等。这些操作通常只需要在应用启动时执行一次，并且对整个应用程序的所有组件都有效。
  * **`Activity.onCreate()`**：主要用于 `Activity` 自身的初始化操作，如设置布局文件、初始化视图控件、绑定数据等。这些操作是与当前 `Activity` 的界面和功能相关的，不同的 `Activity` 可能会有不同的初始化逻辑。

* Ibinder了解吗？

  * `IBinder` 是一个接口，代表了一种跨进程通信的能力。它提供了一种机制，使得一个进程可以调用另一个进程中的对象方法，就像调用本地对象的方法一样。通过 `IBinder`，不同进程之间能够进行数据交换和方法调用，实现进程间的交互。
  * **Binder**：`Binder` 是 `IBinder` 接口的主要实现类，它是 Android 系统中最常用的跨进程通信机制。`Binder` 基于 Linux 的内核驱动，具有高效、安全等特点。在 Android 中，大部分的系统服务和自定义的跨进程通信都使用 `Binder` 来实现。例如，`Service` 组件在进行跨进程通信时，就会返回一个实现了 `IBinder` 接口的对象，客户端通过这个对象就可以调用 `Service` 中的方法。
